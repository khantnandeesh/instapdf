## Gaps

1. **G-1 (check 1, blocks).** Permissions are too coarse and there is one strength. Split "Edit, fill in and comment" so that filling forms and commenting can stay allowed while editing is blocked, and add page changes (insert, rotate, delete) as its own choice; these can sit under More options so the three switches stay. Low-resolution-only printing and an AES-128 choice for old readers are the smaller parts (RC4 is not worth adding). Or get a written waiver from the owner.
2. **G-2 (check 3).** Unlock (and re-protect) of `user-pw.pdf` writes a garbage title, producer and empty dates. The fixture keeps its document info unencrypted inside an encrypted file; the reference copes and returns "InstaPDF test fixture". Files like this exist (older pdf-lib builds wrote them), so detect document-info strings that are not valid ciphertext and keep them as they are. Regenerate the fixture as well and keep the broken one as a named case.
3. **G-3 (check 7).** "Nothing to remove" is shown as an error: the header says "That didn't work.", the button says "Try again" and the console logs a processing failure. Show it as information when the file is read (before the run button is offered), and drop Try again. With several files the unprotected ones are returned in the ZIP with no note.
4. **G-4 (clarity).** At 1280 the owner-password field has no visible label once it holds text (two unlabelled dotted fields in one panel). Keep a short visible label.
5. **G-5 (file size).** Our protected `alpha.pdf` is 2,773 B against the reference's 2,403 B; our unlocked `user-pw.pdf` 2,016 B against 1,676 B. Small; object streams would close it.
6. **G-6 (spec).** The comparison table in the spec is out of date on the reference's default strength (see above). "Restrictions need an owner password typed" on the reference was not tested.
7. **G-7 (coverage).** Not run: the reference with an unprotected file, with restrictions and no owner password, and with RC4 or AES-128; a PDF/A input on ours (AC-814, no fixture); `qpdf --check` (not on this host; every output opens cleanly in qpdf through pikepdf and in PDFium). A re-check of our side needs no new reference tasks.
